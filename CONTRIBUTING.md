# Contributing Guidelines

Thank you for your interest in contributing to this project!

These guidelines explain how team members can report issues, suggest improvements, and contribute changes to the project.

## Reporting Issues

If you identify a bug, an error, or an issue with the project:

1. Check the existing GitHub Issues to avoid creating a duplicate.
2. Open a new issue in the project repository.
3. Provide a clear and descriptive title.
4. Explain the issue, including steps to reproduce it where applicable.
5. Include relevant error messages, screenshots, or other details.

## Suggesting Changes

We welcome suggestions that can improve the project's analysis, code, documentation, or overall quality.

When proposing a change:

1. Open a GitHub Issue describing the proposed improvement.
2. Explain why the change would be useful.
3. Discuss the proposed approach with the team before starting substantial work.

## Submitting Contributions

Please follow this workflow when contributing code or documentation:

1. Make sure your local repository is up to date with the `main` branch.
2. Create a separate feature branch for your work.
3. Make focused changes related to the task.
4. Test your changes and check that the project still runs as expected.
5. Commit your changes with clear and descriptive commit messages.
6. Push your feature branch to GitHub.
7. Open a Pull Request (PR) against the `main` branch.
8. Clearly describe the changes made and reference any related issue.
9. Request a review from at least one team member.
10. Address review feedback before merging the PR.

All contributions must be reviewed and approved by human team members before being merged into the `main` branch.

## Coding and Documentation Guidelines

- Write clear, readable, and maintainable code.
- Use meaningful variable and function names.
- Add comments where they help explain complex logic.
- Keep documentation up to date when project changes affect it.
- Follow the coding and formatting conventions agreed upon by the team.
- Avoid committing temporary files, generated files, or unnecessary data.

## Use of AI Tools

AI tools may be used to support learning, brainstorming, debugging, and drafting, provided their use follows the course's academic integrity requirements.

Contributors remain responsible for verifying all AI-generated suggestions, code, and explanations.

AI tools or agents must not independently open, review, approve, or merge Pull Requests or issues on behalf of human team members. All project contributions and decisions must be reviewed and approved by humans.

Any AI assistance used in the project must be transparently acknowledged in accordance with the course requirements.

## Questions

For questions about contributing, please contact the project team through the repository's GitHub Issues or the team's agreed communication channel.
